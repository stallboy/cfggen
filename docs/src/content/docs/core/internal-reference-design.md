本设计将外键目标扩展到 record 内部具有明确地址的 struct 或 interface 对象。schema 声明目标路径和索引，数据提供定位键，校验与加载阶段解析出类型化的对象引用。实现模块与验收入口见 [实现计划与交付记录](../internal-reference-implementation/)。

## 设计目的

子对象可以继续由父 record 统一编辑、复制和发布，同时获得引用存在性、局部唯一性和目标归属检查。例如，状态机的 Phase 保留在 `phases` 中，跳转直接引用所属状态机内的目标 Phase。

独立子表加复合键仍适用于需要独立维护、跨系统共享的子对象。内部引用解决的是保留内嵌所有权时的寻址需求，不把所有内嵌对象提升为表记录，也不要求所有 struct 都增加 ID。

已有的 [StateMachine 设计](../arch/scene-design.md) 允许任意深度的嵌套，因此同时需要固定路径寻址和显式祖先作用域绑定。

## 已确认的规则

| 项目 | 规则 |
| --- | --- |
| 目标范围 | 支持本 record 和跨 record 的内部对象 |
| 默认起点 | 未声明外部表和记录键的普通内部路径，从当前根 record 出发 |
| 起点选择 | 在 schema 中区分本 record、外部 record、显式祖先作用域；数据为空不改变起点 |
| 目标路径 | 固定写在 schema 中，数据只提供键 |
| 局部唯一性 | 每个集合实例内唯一，不要求整个 record 或所有同类型对象中的键唯一 |
| 显式作用域 | 从当前结构实例自身开始，沿包含关系向上，绑定最近的指定类型实例 |
| 作用域失败 | 找到最近实例后不再尝试更外层实例，也不因键未命中而回退 |
| 作用域校验 | schema 检查类型和路径；数据校验检查每个实际对象是否具有所需祖先 |
| 源键 | 可从当前结构、固定 struct 成员路径、源根 record、显式祖先结构取值 |
| 生成结果 | 保留原始键，生成确定目标类型的派生对象引用 |
| 新声明的 nullable | 整条引用允许找不到目标；不忽略声明、上下文绑定或索引错误 |
| 对象身份 | 不同包含位置的对象不得因字段值相等而混用引用绑定状态 |
| 所有权 | 目标仍归原 record 和集合持有；允许引用环，快照释放后内部环不得阻止回收 |
| 既有行为 | 旧语法表级引用保留历史行为；新增引用采用本文明确的规则，不重设计输入默认值 |

## 集合索引

`index` 声明在集合字段上，而不是元素类型上。它为 `list<明确 struct 类型>` 定义一套局部唯一索引：

```cfg
struct Phase {
    phaseKey:str;
    nextPhaseKey:str ->@StateMachine::phases (nullable);
}

struct StateMachine {
    machineKey:str;
    initialPhaseKey:str ->@StateMachine::phases;
    phases:list<Phase> (index='phaseKey');
}
```

每个 `StateMachine.phases` 独立检查 `phaseKey` 唯一性。不同机器可以各自有 `Idle`、`Done`；同一个集合不能有重复键。声明索引后就执行唯一性检查，不取决于是否已有引用使用它。索引不改变 list 顺序，重排元素不改变引用身份。

每个 list 字段只声明一套索引，可以包含多个直接字段。例如在 Phase 中另外声明 `variant:int;` 后，可以写为：

```cfg
phases:list<Phase> (index='phaseKey,variant');
```

复合键按声明顺序绑定源值。字段存在性和可用键类型沿用现有主键及唯一键规则：

- 键由多个字段组成时，每个字段必须是 `bool`、`int`、`long` 或 `str`。
- 键只有一个字段时，该字段还可以是 struct。这个 struct 可以有多个成员，但成员必须全为上述基本类型，不能包含嵌套 struct、interface 或容器。
- struct 源键与目标键必须属于同一个 schema 类型，仅字段形状相同不算匹配。

拒绝空字段名、重复字段名和非法键类型；`index` 的字符串内容不是表达式，也不是深层字段路径。

`map<K,V>` 直接使用其 map key，不再声明 `index`。如果 map key 是合法的 struct 键，对应一个同类型的完整源值，不自动展开为多个分量。

首版不为 `list<interface>` 推断公共键字段。需要多态目标时，可以使用 `map<K,Interface>`，或用带键的明确 struct 包装 interface 字段。该能力不改变现有输入格式对 list、map 的支持边界。

## 目标寻址

### 起点语法

| 写法 | 目标起点 |
| --- | --- |
| `->::machines.phases` | 当前源根 record |
| `->ability::machines.phases` | 使用源键查找 ability 表主键 |
| `->ability[code]::machines.phases` | 使用源键查找 ability 表的 code 唯一键 |
| `->@StateMachine::phases` | 最近的 StateMachine 结构实例，包含当前实例自身 |
| `->@Act.StateMachine::phases` | 最近的指定接口实现类型实例 |

`::` 分隔表名或作用域类型名与内部路径，避免与现有点分命名空间混淆。其后的点号只表示成员导航。`@` 始终表示显式作用域绑定。

现有 `->table`、`->table[唯一键]`、`=>table[field]` 保持原含义。新增内部对象寻址只接入 `->`，每条新内部引用解析一个目标；首版不扩展 `=>` 的目标路径语义。旧语法 list、map 源字段的逐项引用不受该单目标限制影响。

### 路径规则

目标路径沿包含关系前进，可以经过固定 struct 字段、声明了局部索引的 list、map。每经过一个集合，必须用对应键唯一选中一个元素；固定 struct 字段不消耗键。

终点必须是 struct 或 interface 对象。interface 可以作为终点，首版不穿过 interface 的具体实现继续读取字段，不沿已有外键导航，不扫描所有后代，也不使用通配符或位置下标。

同一种引用结构在多个根表中复用时，本 record 路径必须在所有使用上下文中成立，且终点为同一个 schema 类型。不能让同一个生成访问方法根据使用位置返回不同类型。显式作用域引用的类型与路径在 schema 阶段确定，所需祖先是否存在则按数据中每个对象的实际包含位置检查，见下文的作用域校验时机。

### 本 record

```cfg
table ability[id] {
    id:int;
    machines:list<StateMachine> (index='machineKey');

    startMachineKey:str;
    startPhaseKey:str;

    ->startPhase:[startMachineKey,startPhaseKey]
        ->::machines.phases;
}
```

这条声明先在当前 ability 的 `machines` 中选定机器，再在该机器的 `phases` 中选定 Phase。根 record 已由当前上下文确定，不消耗记录键。

### 跨 record

```cfg
table trigger[id] {
    id:int;
    abilityId:int;
    machineKey:str;
    phaseKey:str;

    ->target:[abilityId,machineKey,phaseKey]
        ->ability::machines.phases;
}
```

源值按以下顺序匹配：

```text
abilityId   → ability 的记录主键
machineKey  → machines 的局部索引
phaseKey    → 所选机器的 phases 局部索引
```

外部表的主键、唯一键或集合索引有多个分量时，依次消费相应数量的源值。若某个键由一个 struct 字段构成，则消费一个同类型源值。检查数量与类型后，终点为 `Phase`，派生引用类型也为 `Phase`。

### 显式局部作用域

`->@StateMachine::phases` 从拥有该引用声明的结构实例开始，沿包含关系向上寻找最近的 StateMachine。这个搜索包括当前实例，因此 StateMachine 自身的 `initialPhaseKey` 与内部 Phase 的 `nextPhaseKey` 可以使用同一种声明。

找到第一个匹配类型实例后，后续路径和键查找都固定在该实例上。例如嵌套状态机 B 中的 `Done` 引用只查 B 的 phases；B 未定义 Done 时，不尝试外层状态机 A。数据为空也不改变这个规则。

作用域不沿外键图搜索。编辑器图中通过外键连接的上游节点，不属于包含关系中的祖先。

显式局部作用域可以处理递归结构中的任意深度状态机；跨 record 引用仍要求目标有固定路径和稳定键。外部直接访问任意深度、没有公开定位路径的匿名对象，不属于首版范围。

## 分层源键绑定

源值定位和目标寻址分别解释。外键左侧是有序的源值路径列表，右侧声明这些值如何定位目标。

| 源值写法 | 取值位置 |
| --- | --- |
| `phaseKey` | 当前引用声明所属结构的字段 |
| `binding.abilityId` | 从当前结构沿固定 struct 字段路径读取 |
| `::abilityId` | 当前引用所在的源根 record |
| `@AbilityUse::abilityId` | 从当前结构开始向上，找到最近的 AbilityUse 后读取字段 |

所有源表达式都有同一个初始上下文：拥有该外键声明的对象。读取某个祖先的字段，不会改变下一个源表达式的起点。左侧 `::` 始终指源 record，不因右侧选择了外部 record 而改变。

### 完整示例

```cfg
struct AbilityUse {
    abilityId:int;
    machines:list<MachineUse>;
}

struct MachineUse {
    machineKey:str;
    targets:list<PhaseTarget>;
}

struct PhaseTarget {
    phaseKey:str;

    ->target:[
        @AbilityUse::abilityId,
        @MachineUse::machineKey,
        phaseKey
    ] ->ability::machines.phases;
}

table ability_use[id] {
    id:int;
    uses:list<AbilityUse>;
}
```

一段 AbilityUse 数据可以保持自然的层次：

```json
{
  "abilityId": 1001,
  "machines": [
    {
      "machineKey": "Combat",
      "targets": [
        { "phaseKey": "Windup" },
        { "phaseKey": "Hit" }
      ]
    }
  ]
}
```

两个 PhaseTarget 都从所属 AbilityUse 取得 `1001`，从所属 MachineUse 取得 `Combat`，然后分别使用自己的 phaseKey。目标是 ability 表记录中的 Phase；这些源数据的祖先结构不是被引用的目标对象。

### 取值限制

源路径只读取单个键值；中间只经过固定 struct 字段，不选择 list 或 map 元素、不穿过 interface 实现、不沿外键导航。终点只允许标量或合法的 struct 键，必须与对应目标键类型兼容。即使目标仍是普通表，新增的源路径也不能以整个 list 或 map 为源值。

祖先按类型显式绑定，不按字段名向上猜测。找到最近实例后，即使它的字段值为空，也不继续搜索外层同类型实例。源值按既有输入规则解析后参与键匹配；未命中按下文新声明的 `nullable` 规则处理。

源表达式读取的始终是源对象的包含上下文。不能在求值中途切换到右侧找到的目标 record，也不能依赖某个派生外键是否先完成绑定。

## 声明和键列表

仅扩展外键源值列表，不改变主键、唯一键和集合 `index` 的本地字段含义。普通表级 `->` 外键也可以复用这一源值绑定机制；首版不将分层源值扩展到 `=>`。

文法结构可按以下方式拆分，具体 ANTLR 规则由实现确定：

```text
key                 := '[' identifier (',' identifier)* ']'
source_values       := '[' (source_value (',' source_value)*)? ']'
source_value        := field_path
                     | '::' field_path
                     | '@' type_name '::' field_path
internal_target     := '::' target_path
                     | table_name key? '::' target_path
                     | '@' type_name '::' target_path
```

`key` 继续用于表主键、唯一键及外部表的唯一键选择；独立外键声明的左侧改用 `source_values`。新增内部引用的行内声明将该标量或 struct 键字段视作一个本地源值，独立声明用于显式指定多个或分层来源。

新增内部引用不接受 list、map 源字段，也不自动广播、按位置配对或构造笛卡尔积。需要多个目标时，使用 `list<引用struct>`，由每个元素分别提供一条引用。旧语法 `ids:list<int> ->table`、`values:map<str,int> ->table` 仍分别按元素、按 value 生成引用，并保留原有的类型及 `nullable` 限制。

固定对象成员不消耗集合键，因此源值列表允许为空：

```cfg
->movement:[] ->::movement;
```

该例要求当前 record 的 movement 是固定 struct 或 interface 字段，直接生成其对象引用。源值数量必须严格匹配定位所需数量；空列表不表示省略本应填写的键。普通表主键和唯一键声明仍不能是空列表。

## 校验和错误

### 作用域校验时机

schema 阶段检查指定作用域类型、源字段路径、目标路径、索引以及键数量和类型是否合法，并确定唯一的返回类型。对于 `@Type::`，类型本身必须可解析，但不要求所有理论上可达的包含路径都已经具有该祖先。

导入、导出及运行时加载中的数据校验按实际对象遍历包含结构，检查源绑定和目标起点要求的祖先是否存在。缺少祖先时报告实际记录与对象路径，并阻止该配置通过校验；`nullable` 不豁免这类错误。

例如，某个 Act 实现声明 `->@Act.StateMachine::phases`，而 Act 也允许用在根部。只要使用该实现的实际数据都位于 StateMachine 内，配置就合法。将该实现放到 StateMachine 之外时才报告缺少祖先；不能仅因其他 Act 实现可用于根部就拒绝整个 interface。

### 新旧声明的 nullable

以下声明使用新的统一规则：目标使用内部路径，或 `->` 的源列表包含新增的固定成员路径、源根路径、显式祖先路径。目标仍为普通表、源值仍全部是当前结构直接字段名的旧语法声明，继续保留现有行为，包括旧容器外键和不同输入来源的历史判定。

规则由声明形式确定，不由数据来源、字段取值或运行时命中情况切换。CFG 读写和内部归一化必须保留这个区别，不能将旧的 `field` 自动改写成 `::field` 等形式而改变语义。

对于新声明，`nullable` 表明整条引用可以不存在。解析并检查全部源路径和所需作用域后，使用输入规则产生的键值进行查找：

| 情况 | 没有 nullable | 有 nullable |
| --- | --- | --- |
| 外部 record 不存在 | 报错 | 整条引用为空 |
| 中间集合元素不存在 | 报错 | 整条引用为空 |
| 最终目标元素不存在 | 报错 | 整条引用为空 |
| 源字段或目标路径不存在、键数量或类型不匹配 | 报错 | 仍报错 |
| 实际对象缺少源绑定或目标起点要求的祖先 | 报错 | 仍报错 |
| 声明索引的键重复 | 报错 | 仍报错 |

`0`、空字符串等解析后的合法键值正常参与查找，不额外约定某一分量为“未填写”哨兵，也不沿用旧语法的主键、唯一键源字段豁免。若这些键实际存在，引用正常命中。输入解析本身的错误仍是错误；本设计不改变 Excel、JSON、pack、sep 的解析和默认值规则，只统一新声明在取得合法键值后的未命中处理。

如果要求 ability 必须存在，但其内部目标可以不存在，可以组合两个独立约束：

```cfg
abilityId:int ->ability;
machineKey:str;
phaseKey:str;

->target:[abilityId,machineKey,phaseKey]
    ->ability::machines.phases (nullable);
```

第一条按原有表级外键规则检查 ability，第二条允许完整子对象引用不存在。无需增加“仅末层 nullable”等语法。任何未命中都不改变起点、不向外层作用域回退，也不返回已经找到的中间对象。

### 错误分类

校验区分四类问题：

| 类别 | 示例 | 处理 |
| --- | --- | --- |
| 声明错误 | 源字段或目标路径不存在、索引字段非法、键数量或类型不匹配 | schema 错误 |
| 上下文绑定错误 | 实际使用位置没有源绑定或目标起点所需的祖先 | 数据校验错误，不被 nullable 忽略 |
| 索引错误 | 同一集合实例的声明键重复 | 数据错误，即使索引暂未被引用也检查 |
| 目标未命中 | 已取得合法源键，但外部记录或某层集合元素不存在 | 新声明按整条引用的 nullable 处理，旧声明保留原有行为 |

诊断应说明源记录、引用名、源值路径、目标起点、失败路径段和使用的键。声明缺少所需作用域与目标集合中不存在某个键，应当能区分。

### tag 裁剪

在选定 tag 的输出 schema 上，重新检查源路径、目标起点、目标路径和索引字段的依赖是否完整。依赖因裁剪被移除时，沿用现有裁剪策略，移除无法成立的关系并给出明确诊断；不自动把被裁掉的字段重新加入输出。

集合保留但索引字段被裁掉时，应移除该局部索引，并继续移除依赖它的内部引用。复合索引不能只删去某个分量后把剩余分量当成另一套索引。最终输出不能保留失效的路径、源绑定或索引声明。

裁剪只处理 schema 依赖的可用性，不能因为某条实际数据缺少祖先或引用未命中就移除声明。保留下来的关系仍须通过完整的数据校验；兼容性检查以裁剪后的有效关系为准。

## 解析和运行时

### 解析顺序

引用目标模型分为三个部分：

```text
起点：CurrentRecord / ExternalRecord / EnclosingScope
路径：固定字段导航与集合索引选择
结果：确定的目标 schema 类型
```

源值绑定是独立的有序描述，使用当前对象、源根 record 和包含关系中的结构栈求值。作用域绑定也使用结构栈；无需为了该功能给所有生成对象永久增加父指针。

处理顺序为：

1. 沿用现有 schema 和数据格式检查，确认字段布局可读取。
2. 确定当前配置实例的最终数据；存在 Mod 覆盖时，先完成该运行时已有的合并。
3. 对最终保留的包含结构建立并检查声明的集合索引。
4. 按实际包含位置检查源绑定和目标起点所需的作用域，为每个源对象取得全部源键。
5. 解析目标路径，按对应声明的未命中规则生成派生对象引用，再进入现有的后续初始化流程。

引用绑定到同一配置实例中最终保留的目标对象，不使用可能已切换的全局默认实例，也不命中已被覆盖对象的旧索引。索引如何缓存、结构栈如何传递属于实现选择，不改变上述语义。

### 包含位置与共享

可寻址目标、依赖包含上下文的源对象，以及承载它们的容器，必须保留每个包含位置的逻辑身份。对象字段值相等不代表它们属于同一位置，也不代表引用结果相同。

例如，AbilityUse 1001 和 2002 内都包含 `{ "phaseKey": "Hit" }`，其 abilityId 从祖先读取。这两个 PhaseTarget 必须分别绑定到各自指定 ability 的目标，不能因为原始字段值相同而共用绑定状态。两个机器中内容完全相同的 Phase 也必须保持各自的局部身份和作用域。

共享底层只读数据可以，但共享优化不得改变寻址结果或混用绑定状态。没有数据字段、只有 `[]` 独立外键的结构仍可能依赖上下文，不能仅凭字段列表为空就将其生成单例或省略引用。无关纯值对象的共享优化可以保留。

父上下文、索引所有者和引用结果缓存必须按对象身份或显式包含位置标识区分，不能依赖仅比较原始字段值的 equals/hashCode。此约束不要求修改所有值对象的相等性定义。

### 循环引用与生命周期

派生引用不改变包含所有权。配置快照有效期间，引用稳定返回该快照中绑定的同一目标；配置切换后，旧快照的引用不能重新解释为新快照中的对象。

允许 `Idle → Run → Idle` 等引用环。快照释放且没有外部持有者后，内部引用环不得阻止旧对象回收。引用计数运行时应使用弱引用加类型化 getter，或其他不会形成所有权环的表示，同时由快照的包含结构在有效期内持有目标。

这一要求尤其适用于 Godot：其 [RefCounted 文档](https://docs.godotengine.org/en/stable/classes/class_refcounted.html) 明确说明强引用环不会自动回收。具体引用表示由生成器实现决定，调用方仍获得确定目标类型的访问能力。

### 序列化

原始数据继续保存字段与键，派生引用在加载后绑定，不重复序列化目标对象。内部引用沿用现有 bytes 编码、包版本和 schema 兼容检查，不增加关系元数据或独立的兼容协议。修改 schema 后同步重新生成代码和数据。

## 实现范围

实现需统一贯穿 CFG 读写、schema 解析与 tag 裁剪、值校验、多语言引用生成、对象共享与生命周期、引用查询与对外 schema 描述。不能只在某一入口解析字符串路径，或让未支持的生成器静默忽略声明。

首版保留明确边界：

- list 使用显式局部索引，map 使用自身键，固定成员直接导航。
- 中间路径只经过静态 struct 和可唯一选择的集合；interface 可以是终点。
- 新内部引用和分层源值引用的每个源值只接受标量或合法 struct 键，多个目标通过 `list<引用struct>` 分别声明；旧容器外键保留逐项引用语义。
- 不增加动态表达式、数组位置寻址、递归通配搜索、跨外键路径导航或任意匿名对象的外部寻址。
- 保留旧语法表级引用、输入默认值和编辑保存策略；新增声明使用本文统一的未命中规则。
- 各语言保留既有数据来源和 Mod 能力边界，不因内部引用要求额外增加这些能力。

## 验收场景

| 场景 | 预期 |
| --- | --- |
| 两个机器的 phases 都包含 Idle | 分别建立索引，不发生冲突 |
| 一个 phases 内有重复 phaseKey | 报重复索引键错误 |
| 没有引用使用某个声明索引，但键重复 | 仍报错 |
| 调整 list 元素顺序 | 引用仍指向相同键的元素 |
| 当前 record 的 machines 和 phases 两级查找 | 返回正确 Phase |
| 跨 record 使用主键或唯一键定位 | 从指定目标 record 继续查内部集合 |
| 复合集合索引或 struct 类型 map key | 按声明顺序及完整键类型匹配，不隐式展开 struct 键 |
| StateMachine 自身的 initialPhase 使用作用域引用 | 绑定自身 phases |
| 嵌套机器 B 没有 Done，外层 A 有 Done | 不向 A 回退，按目标未命中处理 |
| 带作用域依赖的 interface 实现只在合法祖先内出现，其他实现用于根部 | schema 合法，实际数据通过作用域检查 |
| 引用结构实际使用在不具备所需作用域的位置 | 在数据校验阶段报告具体记录和对象路径，nullable 不掩盖 |
| 三个源键分别位于不同祖先及当前对象 | 组合为正确的目标键链 |
| 首个源表达式读取祖先，第二个读取当前字段 | 第二个仍从原始源对象读取 |
| 跨 record 引用同时使用左侧源根路径 | 左侧 `::` 读取源 record，右侧在目标 record 导航 |
| 最近指定祖先字段为空，外层同类型祖先有值 | 不读取外层值；按输入规则取得键，再按新声明的未命中规则处理 |
| 外键图存在上游节点，但包含关系中没有声明祖先 | 不沿外键寻找祖先 |
| 固定对象成员采用空源值列表 | 得到正确类型引用，不额外要求 ID |
| interface 作为 map value 或固定字段终点 | 返回 interface 类型，不猜测实现中的公共键 |
| 新声明在外部记录、中间集合或末层集合未命中 | 有 nullable 则整条引用为空，否则报错，不返回中间对象 |
| 新声明使用 0 或空字符串等合法键 | 存在则命中，不存在则按整条引用的 nullable 处理 |
| Excel、JSON、pack、sep 产生相同合法源键的新声明 | 查找结果和 nullable 判定一致 |
| 旧语法引用在不同数据来源下未命中 | 保留原有历史判定 |
| 父记录有独立必选外键，内部引用有 nullable | 父记录不存在仍由独立约束报错 |
| 目标未命中且另一个源绑定缺少祖先 | 仍报告上下文绑定错误，nullable 不掩盖 |
| 新源路径终点为 list 或 map | schema 拒绝，不隐式展开或配对 |
| 旧 list、map 表级外键 | 保留逐元素、逐 value 引用及原有 nullable 限制 |
| 合法多成员 struct 作为一个键字段 | 消费一个同 schema 类型源值；非法成员类型或不同 struct 类型报错 |
| 两个配置实例或 Mod 覆盖后建立引用 | 各自指向所属实例最终保留的对象 |
| 相同 PhaseTarget 字段值位于不同 AbilityUse 下 | 分别读取对应祖先，绑定状态不共享 |
| 两个机器包含完全相同的 Phase 数据及局部引用 | 保持各自局部身份，引用各自机器内的目标 |
| 无数据字段的结构包含零源值外键 | 按实际包含位置绑定，单例优化不丢失或混用引用 |
| 卸载含 Idle 与 Run 互引的快照，且无外部持有者 | 内部环不阻止旧对象回收 |
| 新旧快照同时存活 | 各自引用保持稳定，不因全局配置切换而改指 |
| tag 裁掉源字段、目标成员或索引字段 | 移除不可用关系及失效索引并给出诊断，不改变复合键含义 |
| CFG 读写及内部归一化往返 | 保留源路径、索引、注释和新旧 nullable 规则的区别 |

上述场景需覆盖 schema 校验、实际数据校验和支持该能力的生成运行时；启用和关闭共享优化时都应满足相同的寻址语义。生命周期场景需覆盖引用计数运行时，兼容性场景需覆盖实际加载入口。

## 运行时与升级

| 运行时 | 新引用保存方式 | 快照与数据来源 |
| --- | --- | --- |
| Java | 类型化对象字段 | 独立 ConfigMgr；在 Mod 最终合并后绑定 |
| C# / Unity | 类型化对象属性 | 独立 ConfigMgr；在 Mod 最终合并后绑定 |
| TypeScript | 类型化对象字段 | 完整单包；新旧对象的绑定分别保存 |
| Go | 类型化对象指针 | 完整单包；重新加载不改变旧对象绑定 |
| Lua | 每个包含位置独立的对象与派生字段 | 每次 cfg 模块快照；共享选项不会合并有上下文的数据 |
| Godot | WeakRef 与类型化 getter | 完整单包；返回的 ConfigStream 持有该快照原始包含树 |

Godot 调用方应在使用配置期间保留 `load_from_package(...)` 返回的 ConfigStream。切换配置后，继续保留旧 ConfigStream 可保持旧引用有效；释放旧快照后，弱派生引用不会阻止其内部环回收。单独持有一个旧子对象不等于保留整个快照。

内部引用和 `index` 沿用版本 1 数据包及原有字段编码。schema 定义引用规则，运行时负责检查索引、作用域和实际引用结果。

升级已有项目时，同步更新生成代码、数据包和运行库；保留了本地修改的支持源码时，由项目合并所需的运行库改动。

启用新关系的 TypeScript schema 将所有 `long` 生成为 `bigint`，需 ES2020 或更新的目标环境，调用方也使用 bigint 键。旧 schema 保持 number 行为。启用新关系且含 `long` 的 Lua schema 要求支持 64 位整数的 Lua 5.3+；新关系不支持 `noStr`，因为寻址需要保留完整字符串键。

局部索引不扩展输入格式能力。例如 map 可继续使用 CSV/Excel 的 pack 映射；不会因此允许 JSON 表输入此前不支持的 map 形式。可以运行仓库中的 `samples/internal-reference` 查看跨层源键和 Phase 循环引用示例。`example/config/combat` 提供各类寻址及键类型的完整游戏验收数据，覆盖说明见该目录的 README；这些数据直接参与六种语言的运行时测试。
